The DevSecOps engineer builds on the hardening work by integrating security checks into delivery workflows and runtime monitoring. Four workflows check application code, images, Kubernetes manifests, and Terraform, bringing security feedback into the development process. The code workflow checks dependencies, exposed secrets, and configuration, giving developers early feedback on known issues. The image workflow checks the Dockerfile, scans the built image, and generates an SBOM before the publish stage. The workflow reports findings across the secure manifests and applies a blocking HIGH or CRITICAL severity gate to the application manifest. Terraform changes receive formatting, validation, configuration, and secret checks against the workflow's configured severity levels and exceptions. CloudWatch tracks operational health, CloudTrail records AWS API activity, and GuardDuty highlights potential threats for investigation. A sample finding tests the GuardDuty, EventBridge, and SNS notification path. The recorded email confirms delivery to the administrator. Policy as code could enforce deployment rules for workload privileges, approved registries, and ownership labels. ESO could synchronize centrally managed values into Kubernetes Secrets, keeping values out of Git while retaining access controls. Network logs, runtime detection, and broader observability could extend visibility. AIOps could help correlate signals, prioritize alerts, and support response automation as monitoring grows. The specialist patches the app and restricts container privileges, Kubernetes access, network traffic, and AWS permissions. The DevSecOps engineer automates checks across all four layers and routes runtime security findings to the administrator.
